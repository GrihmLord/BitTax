# BitTax audit and overhaul — September 2026

Scope: every source file (`src/core`, `src/main`, `main.js`, `preload`, `renderer`), the test
suite, CI and repository contents. Each finding below was reproduced against the code before
it was fixed and is pinned by a test named in the last column.

Severity: **S1** produces a wrong figure on a tax document or leaks data · **S2** wrong
behaviour a user would plausibly hit · **S3** robustness, performance or hygiene.

## Tax correctness

| # | Sev | Finding | Fix | Pinned by |
|---|-----|---------|-----|-----------|
| T1 | S1 | Estimate and Form 8949 summed **every sale ever made** and applied one year's brackets. | Disposals carry `taxYear`; estimate, stats and 8949 export are scoped to the selected year. | `engine.test.js` "summarised per year"; smoke test |
| T2 | S1 | All lots shared one pool regardless of asset: an ETH sale in a mixed history consumed BTC lots, wash sales matched across assets, and the summary added satoshi to wei. | Mixed histories are refused; `calculatePortfolio` audits one pool per asset. | "mixing assets is refused" |
| T3 | S1 | Wash-sale tacking used `min(start dates)`, crediting the gap between sale and repurchase. §1223(3) tacks the *period held*. | `tackedHoldingStart` = replacement date − days held. | "excludes the gap" |
| T4 | S1 | A partial replacement had the adjustment smeared over the whole lot, including units that replaced nothing, and its holding period tacked for all of them. | Replacement units are split into their own tranche. | "split into its own tranche" |
| T5 | S1 | Wash sales ran as a second pass after all sales: HIFO ranked by unadjusted basis, a loss created by an adjustment was never tested, and adjustments were pushed onto sales already reported. | Chronological engine: wash tested at the moment each loss is realised; later sales see adjusted basis. | "cascades forward", "HIFO ranks by wash-adjusted basis" |
| T6 | S1 | Units already sold before the loss sale counted as replacements; other units of the sold purchase could too. | Only held units of *other* purchases qualify (Rev. Rul. 56-602). | "not held", "same purchase" |
| T7 | S1 | Holding period compared milliseconds: bought 15:00, sold 16:00 on the anniversary → wrongly long term. | Calendar-day comparison. | "calendar day, not time of day" |
| T8 | S1 | 29 Feb acquisitions rolled to 1 Mar, reporting a 1 Mar sale as short term (Rev. Rul. 66-7 says long). | Anniversary clamps to month end. | "29 February" |
| T9 | S1 | Capital loss limit was $3,000 for every filer; MFS is $1,500 (§1211(b)). | `capitalLossLimitFor`. | "married filing separately" |
| T10 | S2 | Carryforward had no character; no way to enter a prior-year carryover. | Short/long carryover in and out, Schedule D worksheet order. | "carryovers keep their character" |
| T11 | S2 | Rate tables all `verified: false`; no 2026 table. | 2024–2026 cross-checked against Rev. Proc. 2023-34 / 2024-40 / 2025-32 and pinned figure-by-figure. | `taxTables.test.js` |
| T12 | S2 | Unmatched sales exported `Various` as the acquisition date. | `Unknown`. | — |

## Import

| # | Sev | Finding | Fix |
|---|-----|---------|-----|
| I1 | S1 | Send / Withdrawal / Out rows imported as **SELL**, Receive / Deposit / In as **BUY**: moving coins to cold storage created taxable gains and duplicate lots. | Transfers skipped and listed; swaps flagged; income rows become lots with a notice. |
| I2 | S1 | Zone-less timestamps went through `Date.parse`, i.e. the auditor's local zone: the same file could put a trade in a different tax year on another machine. | Strict deterministic parser; zone-less = UTC; US `M/D/YYYY` fails loudly on day-first files. |
| I3 | S2 | Values were not validated at import; one bad amount aborted the whole audit later. | Every row validated through the engine's own normaliser, errors by line. |
| I4 | S2 | Import **replaced** all history: importing an ETH file erased BTC. | Multiset merge with de-duplication by id or content. |
| I5 | S2 | Positional ids (`import-<line>`, `tx-<index>`) moved labels and freezes to other purchases when a row was inserted. | Content-derived ids. |
| I6 | S2 | Negative sell quantities (Coinbase), a preamble above the header, `Price at Transaction` / `Subtotal` columns, non-USD prices: all failed or were misread. | Handled; non-USD rows refused. |
| I7 | S3 | An unterminated quote swallowed the rest of the file silently. | Reported with its line. |

## Security

| # | Sev | Finding | Fix |
|---|-----|---------|-----|
| X1 | S1 | On Linux without a keyring, `safeStorage` reports available but uses Chromium's hardcoded `basic_text` key: the "encrypted" vault was decryptable by anyone. | `basic_text` treated as unavailable. |
| X2 | S2 | A seed phrase or xprv typed into a label or note was persisted. | Screened in renderer and re-screened at the IPC boundary (txids allowed). |
| X3 | S2 | IPC handlers did not check the sender frame. | All handlers require the top-level `app://bittax` page. |
| X4 | S2 | A corrupted history row of unknown type was coerced into a BUY on load. | Refused. |
| X5 | S3 | Overlapping vault saves raced on one temp file; a clear could be undone by an in-flight save; no fsync. | Serialised queue, fsync before rename, clear removes the temp file. |
| X6 | S3 | Malformed `%` escapes threw inside the protocol handler; non-GET methods and foreign hosts were served. | Rejected (403/405). Added COEP, Permissions-Policy, `no-store`. |
| X7 | S3 | `NODE_ENV=development` enabled DevTools even in a packaged build. | Dev mode needs `--dev` *and* an unpackaged app. |
| X8 | S3 | Lightning heuristic accepted any 62-character string shaped like P2WSH. | bech32 checksum verified. |

## Performance

| # | Finding | Before | After |
|---|---------|--------|-------|
| P1 | Affine scalar multiplication (one modular exponentiation per point op) ran on the Electron main thread, freezing the whole UI. | 200 addresses: **14.2 s** | **0.41 s** (Jacobian; byte-identical output, BIP84 vectors pinned) |
| P2 | Every sale re-sorted every lot ever created. | O(S·L log L) | O((S+L) log L) heap with lazy invalidation |
| P3 | Content ids via pure-JS SHA-256. | 100k rows ≈ 2.5 s | ≈ 1.2 s |

## Hygiene

- Main process converted to ESM (`"type": "module"`); preload is `preload.cjs`. IPC validation
  now imports the engine's own definitions (assets, methods, filing statuses, tx types) instead
  of hardcoded copies.
- Removed: stale React Native research docs, the two redirect-stub HTML pages, Expo assets,
  `tasks/` working notes, and `scripts/finish.sh` (it staged files that no longer existed and
  pushed straight to `main`).
- Removed the float-returning `calculateTax` wrapper, the last path that turned money into a
  JavaScript `number`.
- CI: Node 20/22/24 matrix running a syntax check of every file, the unit suite and verifiers;
  a desktop job that boots the real app under Xvfb and drives it through the UI.
- `persist()` left superseded callers' promises pending forever and nobody saw save failures;
  both fixed.
